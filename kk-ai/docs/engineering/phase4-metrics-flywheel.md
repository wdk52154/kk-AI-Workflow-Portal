# Phase 4：度量体系 + 规范飞轮持续运转

## 核心理念

> 没有度量的改进是盲目的，没有飞轮的度量是静止的。

```
度量 → 发现瓶颈 → 升级规范 → AI 执行 → 度量验证 → ...
  ↑                                      ↓
  └────────────── 持续飞轮 ──────────────┘
```

---

## 度量指标体系

### L1 效率指标

| 指标            | 目标   | 采集方式         |
| --------------- | ------ | ---------------- |
| 平均迭代轮次    | < 3    | 迭代复盘手动填写 |
| 一次性通过率    | > 60%  | 迭代复盘手动填写 |
| 实际/预估工时比 | < 1.5x | 迭代复盘手动填写 |

### L2 质量指标

| 指标           | 目标  | 采集方式           |
| -------------- | ----- | ------------------ |
| 验收失败率     | < 30% | verify.sh 统计     |
| 类型检查通过率 | > 95% | CI 统计            |
| 测试覆盖率     | > 50% | pytest/vitest 报告 |

### L3 规范进化指标

| 指标         | 目标   | 采集方式      |
| ------------ | ------ | ------------- |
| 规范升级频率 | 1-3/周 | Git diff 统计 |
| 规范复用率   | > 70%  | 人工评估      |

---

## 周度复盘流程

### 时间：每周五下午 30 分钟

```
1. 运行 collect-metrics.sh（5min）
2. 填写 weekly-report-template.md（15min）
3. 团队讨论 Top 3 问题 + 下周目标（10min）
```

---

## 飞轮健康度评分

| 维度 | 权重 | 评分标准                                              |
| ---- | ---- | ----------------------------------------------------- |
| 效率 | 30%  | 平均轮次 ≤ 2 → 30分；≤ 3 → 20分；> 3 → 10分           |
| 质量 | 30%  | 一次性通过率 ≥ 70% → 30分；≥ 60% → 20分；< 60% → 10分 |
| 规范 | 20%  | 规范升级 1-3/周 → 20分；0 或 > 5 → 10分               |
| 覆盖 | 20%  | 核心模块都有 TASK → 20分；部分缺失 → 10分             |

### 健康度等级

| 分数   | 等级    | 说明         |
| ------ | ------- | ------------ |
| 90-100 | 🟢 优秀 | 飞轮高速运转 |
| 70-89  | 🟡 良好 | 飞轮正常运转 |
| 50-69  | 🟠 警告 | 飞轮有卡滞   |
| < 50   | 🔴 危险 | 飞轮几乎停滞 |
